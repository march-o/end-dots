# Quickshell in end-dots-martins

The tracked configuration is `dots/.config/quickshell/ii/`; the live Arch configuration is `~/.config/quickshell/ii/`. Edit tracked files first, validate with `sdata/dist-arch/bin/quickshell-ci`, commit the tested source, then deploy with `sdata/dist-arch/bin/quickshell-apply apply`. Never copy changes into a running shell directly. `sdata/dist-arch/setup-martins.sh` has an explicit Quickshell file list; add any newly changed file that needs to survive `./setup update`.

## Shared widget foundation (required)

- Start every new floating Quickshell widget with `GlassPanelWindow` containing `GlassPanel` from `modules/common/widgets/`. Set `panelName`, bind `shown`, choose `slideFrom`, and handle `dismissRequested`. The window supplies a `quickshell:glass-*` namespace, focus dismissal, animated pointer mask, and slide lifecycle; `GlassPanel` inherits its namespace and supplies the wallpaper-aligned blur, shared tint/edge, padding, and semantic colors. Use `frameInset` for outer clearance and `contentPadding` for the content inset; children are already placed inside that padding. Compact bar islands and animated media frames can retain their existing `BarGlassIsland` geometry.
- `modules/common/GlassColors.qml` is the shared semantic palette; the former sidebar-only palette has been removed. Standard controls inherit it through `ScopedColors`. Use `GlassTextField` for text entry, `GlassButton`/`GlassIcon` for icon actions, and the panel's `statePalette` (icons) or `textStatePalette` (labels) for explicit states. Keep tile/group backgrounds transparent and avoid independent hard-coded colors, opaque plates, or outer shadows.
- Keep native compositor movement disabled for `quickshell:glass-*` surfaces. `PanelSlide` animates their contents inside fixed windows, retains the surface through exit, and reverses smoothly on reopening. A compositor slide carries a pre-rendered wallpaper crop with the window, producing a stuck-on-image effect that QML cannot track. `GlassWallpaperBackdrop` updates its window-local crop with `FrameAnimation`, including media expansion; do not restore a low-frequency timer. Validate stationary screen samples at multiple intermediate slide positions, plus opening/closing/reversal and pointer-mask movement.
- Bind the native window's `visible` to `PanelSlide.presented` (the explicit `shown || progress > 0` lifecycle state), never to the child item's `visible`. Qt item visibility includes hidden ancestors, so that feedback can keep a dismissed layer surface permanently hidden. A FloatingWindow/offscreen substitute missed this failure. Test actual `GlassPanelWindow` native surface teardown and reopening with a transparent 1×1 panel, an empty input mask, keyboard focus disabled, and a stub focus manager so the test cannot affect user input; verify both slide directions and content unload/reload.
- Improve the shared components when a new widget needs a reusable capability. Do not copy the palette or backdrop into a widget and plan to restyle it later. Add new files to the Arch setup list, remove obsolete live files during migration, and verify both the new widget and an existing consumer after shared changes.
- Keep `GlassPanelWindow` instantiated and put expensive content in a child `Loader` whose `active` follows the window's `visible`. This retains content through exit and unloads it afterward. Do not bind an outer Loader's `active` to its own `item.visible`: destroying the window changes that dependency and causes a binding loop on close.
- Register shared glass windows with `GlobalFocusGrab` only after `backingWindowVisible` is true, deferring registration with `Qt.callLater` so native surface and keyboard-focus changes settle. Remove them immediately when `shown` becomes false, before the exit animation finishes. Validate repeated global dismissal and reopening with focus registration assertions; animation-only open/close checks do not cover outside-click handling.

```qml
import qs
import QtQuick.Layouts
import qs.modules.common.widgets

GlassPanelWindow {
    panelName: "myWidget"
    shown: GlobalStates.myWidgetOpen
    slideFrom: "top"
    onDismissRequested: GlobalStates.myWidgetOpen = false
    implicitWidth: 600
    implicitHeight: 400
    GlassPanel {
        anchors.fill: parent
        ColumnLayout {
            anchors.fill: parent
            StyledText { text: "My widget" }
            GlassTextField { placeholderText: "Search" }
        }
    }
}
```

## Local CI and deployment (required)

- Read `sdata/dist-arch/QUICKSHELL-CI.md` for the commands, dependency setup, and limits. Run `quickshell-ci` for every Quickshell change. It tests the complete root, pinned submodules, known-good → candidate hot reload, separate cold start, rendered native bar, actual hover surfaces/reopening, passive focus, Ash states, font scale, and return to the baseline. A small component harness or `qmllint` alone does not establish that the full shell loads.
- Tests run in bubblewrap with a private headless Sway compositor and bus, no network, and no host display/input/session sockets. Hyprland read data is a fixture; Hyprland-only protocols still require real live checks. Baseline sandbox service diagnostics are recorded; any new runtime diagnostic fails. Include a live notification in an unchanged-baseline self-reload before testing the candidate: Quickshell 0.3.2 can emit notification-wrapper teardown warnings even without source changes. Live apply can accept only exact reproduced warnings from byte-identical QML files, never errors or changed components. Inspect the generated images before deploying UI preferences. CI captures populated bar histories at both font scales; reset the grab completion flag before each capture so a previous frame cannot satisfy a later check.
- Commit the tested Quickshell source before `quickshell-apply apply`. The tool runs CI unless given `--report /path/result.json`; reports expire after 30 minutes and bind source, tools, tests, Quickshell version, baseline, and preserved live customizations. Source or test changes require another run. `setup update` routes a running shell through the same guard.
- `quickshell-apply` records Git references and hashes, never backups. Initial adoption requires `quickshell-apply adopt --ref <commit-matching-the-live-release>` with a fresh successful live load and native bars. Unknown state, lock, sleeping displays, multiple instances, live drift, unexpectedly missing/duplicate bars, or uncommitted source stop deployment. A bar suppressed by actual fullscreen on a visible workspace is expected; verify the native monitor/client mapping rather than exiting Moonlight to reveal it. Apply verifies the same suppressed outputs and fresh shell generation afterward. Use `--no-color` for log parsing across installed CLI versions. Preserve unrelated live customizations; a touched file must match the recorded Git baseline so recovery is possible.
- Apply pauses file watching for the batch, writes in place, and requires a fresh generation plus visible stats content on every existing bar output. Bootstrap uses a short stop/resume with an independent resume watchdog; it never terminates the shell. Failed applies restore touched files from the recorded Git commit and verify a fresh restored load. Never kill a retained valid generation merely because a reload failed. A process crash or unavailable lock IPC requires diagnosis, not an automatic restart that could expose a locked session.
- New inline QML components can pass isolated cold tests yet fail full-root reload with `X is not a type`. Test both paths with the installed binary. Introduce reusable components as normal shared QML files instead of solving this through repeated live reloads. A successful old IPC reply or old `Configuration Loaded` entry does not prove the new generation loaded.

## Live changes

- Night Light preferences live in `~/.config/illogical-impulse/config.json` under `light.night`; the watched JSON applies temperature changes without a shell reload. Arch setup restores the temperature and schedule from `config/devices/{desktop,laptop}.env`. Scheduling uses the machine's local clock; both machines use `Europe/Riga`, including daylight saving changes. Verify application with `hyprctl hyprsunset temperature`. Sunshine screen capture excludes the host's Hyprsunset tint, so set the laptop's own Night Light for Moonlight playback.
- After a system Qt upgrade, run `qs --private-check-compat`. The locally built `illogical-impulse-quickshell-git` package is not updated by AUR helpers; if the check reports a Qt version mismatch, rebuild the pinned PKGBUILD in `sdata/dist-arch/illogical-impulse-quickshell-git/` against the installed Qt and install the resulting package. Verify compatibility again before the next shell launch. Package replacement does not require restarting the running desktop or lock UI.
- The pinned source needs `qt612-metatypes.patch` for Qt 6.12: replace opaque QObject pointer declarations with `Q_MOC_INCLUDE` and define bindable getters in source files where the pointed-to classes are complete. Otherwise cached incomplete-type checks cause `Meta Types must be fully defined` errors in the Hyprland, i3, and PipeWire modules. Keep this patch in the Arch PKGBUILD's `prepare()` step.
- Before any live copy, edit, or reload, check the lock state with `qs -c ii ipc call lock isActive` and monitor `dpmsStatus` with `hyprctl monitors -j`. If locked, displays are off, or the lock state cannot be confirmed, finish changes in the tracked tree and defer live deployment until the user unlocks and wakes the displays. The passwordless overlay's `GlobalStates.screenLocked` resets on reload, which can expose the desktop and wake an off display. Never use a reload as a way to wake or unlock the user's session.
- Inspect the current instance with `qs list --all` and read recent errors with `qs -c ii log --tail 50`. Confirm `Configuration Loaded` after edits and that no newer `Failed to load configuration` remains.
- The `qs log` binary-log decoder can time out on a long-running shell even while IPC and the shell remain healthy. Read the matching instance's text log at `$XDG_RUNTIME_DIR/quickshell/by-pid/<pid>/log.log` in that case; verify the PID still matches afterward. The deployment guard uses this path first so log decoding cannot trigger unnecessary rollback. A failed verification still requires checking the restored files, fresh generation, lock IPC, and native bars; never restart the shell to repair the log reader.
- If the lock screen has no wallpaper to blur, check `~/.config/illogical-impulse/config.json` at `.background.wallpaperPath` and confirm the referenced image exists. The background QML uses that setting as its image source, and the lock blur operates on that image; a generated `wallpaper/path.txt` alone does not select the live Quickshell background.
- The wallpaper `StyledImage` has `retainWhileLoading: true`, but an opacity binding to `status === Image.Ready` hides the retained frame during each async image load. Keep opacity independent of loading status for an uninterrupted switch.
- Successful unlocks go through `LockScreen.finishUnlock()`, which guards against duplicate completion and runs `~/.local/bin/wallpaper-next --random` by absolute path after clearing the lock. Quickshell can inherit a compositor PATH without `~/.local/bin` even when the interactive shell finds the command; test using the running shell's environment and verify the configured wallpaper actually changes. Keep this out of shell startup and generic visibility handlers so reloads and failed authentication never rotate wallpaper. Random selection excludes the current image, unsupported files, and directories; a collection with only the current image is a no-op. Preserve the helper's sequential mode for existing callers.
- Use the guarded apply result as the deployment gate. Only capture the live design after it verifies a fresh successful generation and the changed content is visible. Save review captures to new paths to avoid cached images.
- Quickshell generates module type information from local QML files and their `pragma Singleton` declarations. Do not add a partial `qmldir` for a new singleton: it replaces the generated module inventory and can make existing types such as `Bar` unavailable. Use the existing automatic module discovery.
- Avoid a generic `palette` id for sampler objects: controls expose a `palette` property and inline or delegate scopes can resolve it instead of the outer id. Use a distinct id such as `localColors`, bind inline components to their root’s explicitly named state properties, and provide a fallback palette during initialization. Check for startup warnings after `Configuration Loaded`, too.
- This QML parser accepts array spread but rejects object spread (`{ ...state }`) at load time. Use `Object.assign({}, state, changes)` when merging playback state, and verify a fresh successful load after applying it.
- A QML `Behavior` needs a writable property. Animating a `readonly property color` makes the shell fail to load; keep a bound animated color as `property color` instead.
- Keep `import Quickshell.Hyprland` in a panel that declares `GlobalShortcut`; removing it makes the entire shell configuration fail to load. After a failed reload, check for the newest `Configuration Loaded` before trusting older errors in the log.
- Use `shellControl.reload` only within the guarded deployment path; do not touch live `shell.qml` to force an uncertain reload.
- Remove temporary logging or IPC probes from tracked and live QML after diagnosis. Do not restart the shell casually: the lock UI runs there. For lock changes, ensure a working recovery path and verify that the shell loaded before trying to lock.
- If content changes and an in-place `shell.qml` edit do not reload, check `qs -c ii ipc call lock isActive` before replacing the instance. `qs kill` can report success while the old PID still runs; verify that it exited before launching a replacement, or two bars can appear. After replacement, check `qs list --all`, lock IPC, and a screenshot.
- A long-running instance can keep rejecting a newly introduced inline component after discovering its files; a cold start with the same files resolved `UtilityButton is not a type` on the laptop after repeated failed reloads. Inspect the complete error chain and confirm the files first; only replace an unlocked, awake instance after verifying its old PID exits.
- When replacing the shell remotely, launch it through the compositor with `hyprctl dispatch 'hl.dsp.exec_cmd("qs -d -c ii")'`, rather than directly from SSH. An SSH-launched shell belongs to the remote login session, even with Wayland and D-Bus environment variables set; NetworkManager then requests administrative authentication for Wi-Fi scans. Preserve the desktop session's environment and verify the new process belongs to its local session instead of weakening Polkit rules.

## Screenshot actions

- The bar screenshot button, `region screenshot` IPC, and `regionScreenshot` global shortcut share `RegionSelector.qml`. The final mouse-button action is chosen in `RegionSelection.qml`, overriding the initial action; changing only `RegionSelector.screenshot()` does not change left-drag behavior. Keep `CursorGuide.qml` in sync with that mapping. On Arch, left-button selection opens the configured annotation editor and right-button selection copies directly. On this desktop, full-screen capture dropped from about 0.78s to 0.04s and editor-input cropping from 0.34s to 0.12s; Swappy window startup was about 0.22s. Keep normal encoding for saved output.

## WireGuard controls

- `vpn_lock` is supported by the installed Material Symbols font and shows a globe with a lock, distinguishing VPN controls from the screen lock. The bar's screen-off lock control reuses `tv_off` from `LockSurface.qml`.

## Keep this skill current

### Optional app HyprGlass

- Arch's `custom/glass.lua` configures HyprGlass v0.9.1 for Hyprland 0.56.2, when a matching build exists at `~/.local/share/hyprglass/hyprglass.so`. Build the plugin against the installed Hyprland headers and the upstream release pinned for the running compositor commit; do not load an arbitrary latest build. Missing/incompatible builds leave the wallpaper-only bar unchanged.
- Keep environment initialization idempotent across compositor config reloads. `hyprland/env.lua` deduplicates `XDG_DATA_DIRS` while retaining custom directories: repeatedly appending its own current value once grew the variable to 1.3 MB, causing `E2BIG` ("Argument list too long") and silently preventing app launch shortcuts. Measure only environment variable lengths when diagnosing, never print credentials. Recover by deduplicating the compositor's existing value through `hl.env` in a live eval; do not restart the desktop or discard custom search paths. Stage the corrected Lua file with autoreload disabled, restore the prior setting, and test both app launch and Super overview input.
- Declare `hl.plugin.load(path)` on **every config parse**, including when `hl.plugin.hyprglass` already exists. Guarding the declaration with `if not hl.plugin.hyprglass` makes Hyprland omit the loaded plugin from its desired config list, unload it, then load it on the next parse: a reload loop that can stall the desktop and grow compositor memory. Guard only file/version availability and the subsequent configuration calls. A load declaration made through `hyprctl eval` alone does not necessarily load the plugin immediately; the explicit `hyprctl plugin load path` command does.
- Keep `enabled = false`, `manage_window_blur = false`, and `layers.enabled = false`. Only the explicitly tagged Chrome/ChatGPT apps use HyprGlass. The bar uses its own wallpaper crop and a `blur = false` layer rule; global window blur settings stay unchanged. Verify `hyprctl -j hyprglass status`, `hyprctl configerrors`, and stats before screenshots: layer draw counts must stop increasing while tagged app draws still work.
- HyprGlass layer lens geometry uses the full native surface bounds even when alpha masks clip multiple islands. The tall surface reserved for stats/media expansion pulls dark application edges into the compact pills, appearing as a black underline. Use `GlassWallpaperBackdrop` throughout both states, with compositor layer glass disabled, to isolate the bar from windows. Keep the per-island QML reflections: `BarGlassIsland.qml` uses an inset rounded gradient, and a continuous Canvas outline that fades from a restrained upper highlight into a palette-colored lower edge. Internal etched seams stay inside the same glass pill; keep their coordinates based on shared layout spacing. Their alpha stays inside the existing frame, with `visible` tied to its border width so transparent content groups remain clear.
- This Lua-based Hyprland rejects `hyprctl keyword`; use `hyprctl eval 'hl.config({...})'` for live changes, including `misc.disable_autoreload` when staging watched config files. Plugin loading itself schedules a compositor config reload, so verify the active workspace and focus afterward; do not restore stale focus if the user has interacted.
- HyprGlass v0.9.1 `hg.preset()` queues definitions until the config-reloaded callback commits them. A successful live eval does not activate a preset. Stage it and perform one guarded compositor config reload, preserving focus and monitor geometry; do not unload/reload the plugin. `hg.config()` numeric settings can still update live. Verify actual opacity with `hyprctl getprop address:... opacity`.

- A preset reload does not explicitly invalidate HyprGlass's existing window background samples. Verify that `windowCacheMisses` increases on the visible app's monitor. Keep this short and never leave the cache disabled; loading the new preset and checking tags alone does not prove a static window has reblurred its background.
